## Intent
Every `@softure-ai/*` package is on its newest published version, as the package-update routine
(`routines/package-updates.md`) describes.

## Context
Two packages move: `@softure-ai/theme-notion` 0.37.0 → 0.41.1 and `@softure-ai/deploy` 0.7.9 → 0.7.10. The rest
are current (auth 0.2.24, core 0.2.11, db 0.1.17, jobs 0.1.15, mailing 0.3.0, mcp-access 0.7.9, observability 0.8.8,
ops 0.2.6, security 0.2.12, theme-kit 0.1.10, ui 0.3.11, config 0.1.7, skills 0.41.1, testing 0.6.0). No held
packages, no owner steps (`routines.packageUpdates` absent), no open package-update pull request.

What the release notes ask of this app:
- theme-notion 0.37.1, 0.38.0, 0.40.0: nothing (touch targets in `RowActionsMenu`, a new `HelpTooltip`, the
  `Checkbox` indeterminate state; the app has no own indeterminate override).
- theme-notion 0.39.0: new `DatePicker`/`DateTimePicker` and `sideLayout="inline"` on `ListEntry`/`FoldRow`. Both
  are optional; adopting them replaces the app's native date and time inputs and `app/row-layout.css` on every list,
  an app-wide UI rollout, which the owner's standing order sends to roadmap items of their own.
- theme-notion 0.41.0 (migration): the scheduled-task dialog's `size="wide"` plus its own scroll classes and its
  own sticky footer classes become `size="form"` and `DialogFooter sticky`.
- theme-notion 0.41.1: the theme centres a linked row's arrow on a one-line right column; the app's
  `[data-slot="list-entry-side"]` rule "can go" only together with `sideLayout="inline"` (above), so it stays.
- deploy 0.7.10: nothing but moving every `uses:` pin to the `deploy@0.7.10` commit
  (`ed3227cd311b8a14d0cc5af04280bb7bd893983c`), with `DEPLOY_CLI`, `TOOLS_IMAGE` and the "generated by" lines; the
  package's templates are unchanged.
